# Human Review Workspace

TakeTwo — Speech analysis workspace. This browser editor wraps the existing Phase 3 `Review` v1, `Interval`, `Label`, provenance, validation and consensus contracts. It does not alter acoustic algorithms, `delivery-v0`, dataset schemas or independent-review requirements. [Executed verification](review-workspace-validation.md) distinguishes software checks from outstanding human acceptance.

## Operator preparation and sequential handoff

1. Import the actual recordings and draft transcript. Run analysis with native MFA if timing suggestions are needed. A transcript check can start without alignment; timing requires a successful, current MFA artifact. Flaw review requires an existing participant pair.
2. Open **Review Workspace**. In PowerShell, read the operator key from the active workspace: `Get-Content (Join-Path $workspace '.review-operator-key')`. Keep the key private. Enter the actual assigned reviewer pseudonym, recording, activity and optional original alignment job. Do not invent reviewer consent, identities or independence.
3. Close other operator/analysis tabs and use a fresh private browser window per reviewer. Start handoff. The page reloads into an isolated reviewer application; it does not mount the analysis application or fetch peer data. The capability is exchanged for an HttpOnly, SameSite=Strict cookie, scoped to review routes. Its fragment is removed from the address bar. Do not share the capability with another reviewer.
4. While handoff is active, the backend rejects general recording, analysis, feature, score, dataset, evaluation, peer review, inventory and OpenAPI routes, even if an operator header is supplied. Only the active session's capability-protected routes, the mode indicator, static UI and operator unlock remain available. Filenames that could reveal intended delivery are replaced by “Assigned recording”; recipe/intended-label metadata is not included. Blinded flaws receive no MFA suggestions, detections or scores; assigned reference audio is available as listening context.
5. After the reviewer saves/submits, the operator ends handoff with the private key. Close the reviewer window and discard its browser storage before opening peer evidence. Drafts persist across service restarts; active handoff stays locked. Resume through the operator inventory rotates the capability and revokes the old one.

This is a supervised, sequential local workflow, not multi-user authentication. A typed pseudonym does not prove identity, independence, consent or comprehension. The trusted filesystem owner can read the key, audio, database and other evidence; another process under that OS account is outside the protection boundary. Previously opened tabs/downloads cannot be erased by this service. Do not give unattended reviewers access to the OS account or an unlocked workstation. For stronger independence, use separate supervised OS accounts/devices and isolated workspace copies containing only assigned audio/text/alignment, collect exported reviews privately, then import them on the operator workstation. Never include peer reviews, reports, recipes, private rights files or operator credentials in handoff copies.

## Reviewer activities

Use **Listen from beginning** and native playback, seek, numeric selection start/end in milliseconds, adjustable replay context and **Zoom to selection**. Keyboard arrows operate native range/number inputs. Waveform dragging selects intervals; near a selected timing word's vertical edges it adjusts boundaries. Numeric controls provide every essential operation without dragging. Suggestions and human edits remain separate. The word list shows actual MFA labels/times and neighboring words.

- **Transcript:** inspect the supplied text and optional machine spoken forms. Correct missing, extra or wrong words and repetitions in the separate reviewer text. Mark unclear selections and supply listening notes. Changed canonical words trigger an alignment-regeneration warning; no old timing approval transfers. An approved correction still requires two agreeing checks and an explicitly reviewed new dataset version, followed by regenerated artifacts.
- **Timing:** explicitly load MFA suggestions for inspection. Loading does not approve them. Enter phrase-ending word numbers, comma separated, including the last word: e.g. `8, 15, 23` partitions tokens `[0,8)`, `[8,15)`, `[15,23)`. Define this from actual speech, not the example. Listen, adjust native start/end milliseconds, save, and mark each saved boundary inspected. A changed word clears its inspection marker. Negative, zero-width, overlapping, unordered, incorrect-token and out-of-audio intervals are rejected. Mark uncertain words; uncertainty prevents an approved decision until resolved.
- **Blinded flaws:** independently listen to the participant and assigned reference context. Select an interval, category, severity, audible rationale and optional uncertainty. Existing categories are pacing, pause behavior, energy variation and pitch dynamics. Missing/shortened pauses may use an exact boundary anchor instead of invented silence. Edit/delete draft labels. Empty labels mean no positives only across actually listened coverage. Unknown uncertainty stays null; zero must be an explicit judgment. Recording-quality defects and alignment uncertainty are not new flaw categories.

**Save draft** reports success/error explicitly. Failed saves retain local edits. Saving is explicit rather than autosave, to avoid committing intermediate invalid intervals. Unsaved changes trigger the browser's leave warning. Reload restores saved evidence; optimistic edit revisions reject stale tabs. Playback events and inspection markers persist independently. Short listening events must follow real-time playback; seeks do not count as listened spans. Coverage is the union of observed playback intervals, without filling gaps. Submission requires exact full-recording coverage, evidence reference, notes, explicit independence/blinding declarations where applicable, valid scope evidence and every timing word inspected. These interaction checks cannot establish that a human understood the recording.

Choose **Unresolved**, **Rejected**, or **Approved after inspection** deliberately. Unclear speech/uncertain word boundaries cannot be approved. **Check completion** lists missing actions. **Submit review** never defaults to approval and writes an immutable, hash-addressed Phase 3 artifact. Submitted controls are read-only; corrections require an explicit same-reviewer, same-subject `supersedes` session. No original source, alignment or prior review is overwritten.

## Export, import and adjudication

After submission, **Export scientific Review JSON** downloads exactly the existing `Review` contract accepted by CLI `import-review` and the existing web reviewer-file importer. Session summary includes draft/submitted state, annotations, original/machine/corrected text, listening/inspection actions, provenance, integrity and validation. A summary is a lifecycle document, not a scientific Review import; incomplete drafts cannot use the scientific export endpoint.

After ending handoff, use the existing **Import an actual reviewer file** control for legitimate external evidence. Choose its corresponding analysis job. Existing provenance/alignment/pair validation applies; importing never authenticates the reviewer or marks dataset text verified.

The operator inventory shows original submissions, corrected texts, word bounds, phrase partitions, labels, severity, uncertainty/rationale, coverage and supersession history. Existing consensus reports transcript disagreements, >200 ms timing disagreements, phrase differences and nonidentical flaw inventories. An authorized operator supplies an adjudicator identifier, explanation and resolution, which are timestamped separately. Disputed evidence remains `awaiting_reviewer_revisions`; an adjudication note cannot override consensus or create approval. Each reviewer must revisit audio and submit a superseding review explicitly. Preserve original blind submissions; reconciled revisions are adjudicated evidence, not fresh blind-independent annotations. Flaw consensus requires identical reconciled label IDs, locations, categories, severities, rationales, uncertainty and coverage; agree these explicitly after both original submissions, never silently select one inventory.

## Storage and integrity

`review-workspace.sqlite3` uses WAL, a five-second SQLite busy timeout and schema version 1. Additive session/handoff/adjudication tables are separate from the unchanged job database and authoritative dataset manifest. There is no recording/data migration. Draft writes use SQLite transactions; edit revision conflicts return 409. Capability digests, not raw capabilities, are stored. Session payloads carry an internal canonical digest and a database envelope digest. Submission validates current canonical audio/sample/text, full recording metadata, processing versions/source hash and pinned alignment payload hash. IDs/SQL queries are bounded/parameterized; no HTTP filesystem path is accepted. Review requests are capped at 1 MiB. Private keys and SQLite sidecars are ignored by Git.

Final evidence uses existing exclusive, content-addressed `derived/comparison-v1/review-<hash>.json` publication. A crash between publication and SQLite commit may leave a valid submitted artifact with a draft lifecycle row; the operator must inspect that artifact/action history before retrying or creating a revision. Do not delete or edit scientific evidence to repair lifecycle state. Back up both databases and immutable artifacts together while stopped. Losing the operator key blocks handoff recovery; restore the backed-up key, not an invented identity.

Review edits never invoke MFA, feature extraction or a CPU job. Existing audio and bounded waveform endpoints are reused; waveform results change only with the native view window, not each boundary edit. The serial worker, duration/file limits, cancellation, crash containment, deadlines, cache integrity and scientific gates are unchanged. General analysis resumes only after handoff ends.

## Human acceptance checklist

The five private same-speaker takes remain genuine recordings, unverified ground truth. Automated browser drafts demonstrate editing/playback only; they are labeled software checks and never submitted as production reviews.

1. Recruit two actual independent reviewers who did not perform the takes; record actual identity mapping/conflicts and lawful permission privately.
2. For each of reference, natural, slow, uneven and near-perfect: independently listen/check exact text, then resolve differences with retained originals. Use reviewed text in a new dataset version and regenerate MFA/features; do not patch verification flags.
3. Each reviewer listens to every member and manually inspects every word/phrase boundary. Retain uncertainty and all failed/disputed cases.
4. Each reviewer labels participants without predictions, scores, recipes or intended filenames; listen to the whole clip and record clean/unclear coverage honestly.
5. Submit real reviews, export/check hashes, end handoff and adjudicate disagreements. Each author explicitly submits required revisions. Re-run comparisons/evaluation with original gates; expect abstention until all required evidence is available.
6. Have an actual person verify keyboard use, spoken screen-reader announcements and native 200% browser zoom. Software interaction checks do not close those human gates.

No rights clearance, independent review, real accuracy, calibration, held-out evaluation or public release is implied by having two session records.
